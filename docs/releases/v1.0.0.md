# Z-Image on Kaggle TPU v5e-8 — v1.0.0

> 🌐 Language / Ngôn ngữ: **English** | [Tiếng Việt](https://github.com/dangkhoa2016/Z-Image-On-Kaggle-TPU-v5e8/blob/v1.0.0/docs/releases/v1.0.0.vi.md)

## First public release

`v1.0.0` is the first community-facing release of a reproducible **full, undistilled `Tongyi-MAI/Z-Image` inference stack for Kaggle TPU v5e-8**. The release is built around a measured production configuration rather than a minimal “model boots” demonstration: one PJRT process uses all eight TPU devices with a `(replica=4, model=2)` mesh, BF16 transformer inference, four concurrent 1024×1024 outputs, and versioned evidence for the claims published below.

The repository does not redistribute Z-Image weights. Prompt encoding and VAE decode remain CPU-side; transformer denoising runs on TPU through PyTorch/XLA with manual SPMD parameter sharding.

## What v1.0.0 establishes

- **Full-model execution:** no GGUF, quantization, or distillation in the accepted transformer path.
- **All eight TPU devices used:** 521 transformer parameter tensors are sharded in the accepted runtime.
- **Production topology:** `(replica=4, model=2)` with global batch 4 at 1024, producing four images concurrently.
- **Measured 1024 throughput:** 90.264 s for four 1024×1024 outputs (`0.04431 img/s`, 22.566 s/image amortized).
- **Measured HBM boundary:** global batch 4 is the maximum safe tested batch at 1024; batches 5–8 fail XLA compilation under HBM pressure.
- **Resolution-aware execution:** batched CFG for standard workloads, sequential CFG for lower peak HBM, and full-context query-chunked attention for very-high-resolution validation.
- **Validated stretch boundary:** 2560×2048 (5.24 MP), using sequential CFG, query chunk 4096, and explicit XLA synchronization.
- **Reviewable publication evidence:** fixed prompts/seeds, runtime identity, benchmark JSON, acceptance reports, output hashes, accepted images, regression tests, and repository audit gates.

A fresh Kaggle TPU execution of the same four-seed 1024 workload completed in **90.099 s**, with warm transformer-forward median around **1.262 s/step**.

## Historical topology evidence

Before freezing the 4×2 production path, the project measured a matched two-image workload using `(replica=2, model=4)` against a 1×8 model-mesh control:

| Resolution | 1×8 model mesh, batch=2 | `(replica=2, model=4)`, batch=2 | Pair speedup |
|---:|---:|---:|---:|
| 512×512 | 126.264 s | 95.001 s | **1.329×** |
| 1024×1024 | 288.645 s | 127.218 s | **2.269×** |

This remains historical matched-control evidence, not the current production recommendation. An independent multi-chip-subset PJRT experiment also failed before model loading; accepted multi-replica paths therefore use one PJRT process across all eight devices.

## Reproducibility contract

The public release separates three kinds of information:

1. **Implementation** — reusable runtime modules, scripts, tests, and the clean Kaggle execution template.
2. **Measured evidence** — JSON/Markdown records for topology, timings, prompts, seeds, failures, and accepted output hashes.
3. **Interpretation** — README and technical documentation explaining what the measured evidence means and where the validated boundary ends.

Publication gates include the CPU-safe pytest suite, Python compile checks, repository audit, evidence JSON parsing, and showcase hash verification. ## Quick start

1. Use a Kaggle TPU v5e-8 session.
2. In the Kaggle notebook, choose **Add Input → Models**, then select the [Tongyi-MAI/Z-Image mirror](https://www.kaggle.com/models/dangkhoa2016/tongyi-mai-z-image) (**PyTorch / default / version 1**). Check that its read-only mount contains `model_index.json` at `/kaggle/input/models/dangkhoa2016/tongyi-mai-z-image/pytorch/default/1`.
3. Load the tagged `v1.0.0` source and install the pinned user-space dependencies while preserving Kaggle's PyTorch/XLA runtime.
4. Run the BF16 TPU health check and live `(replica=4, model=2)` mesh probe.
5. Run the 512 smoke path and the 1024 global-batch-4 production workload.
6. Keep pair-throughput and high-resolution qualification disabled unless you intentionally want the longer experiments.

Start with the [README](../../README.md) for the project overview and [Kaggle Runtime Guide](../KAGGLE.md) for execution details.

## Scope and licensing

This release validates inference, not training or fine-tuning. Very-high-resolution execution is a capability boundary and is substantially slower than the normal production path. Generative quality and prompt adherence still require visual review.
